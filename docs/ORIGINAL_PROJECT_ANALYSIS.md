# Анализ исходного проекта SDL_Moskalev

## Объект и метод анализа

Исходный репозиторий: https://github.com/ilya20012021/SDL_Moskalev

Дата анализа: 19 октября 2026 года.
Ветка: `master`. На момент получения исходников API GitHub сообщил коммит
`f43ded05a034bee213ca20e56bd457aa37d173b7`.

Проведён статический анализ файлов `main.py`, `convJson.py`, `convXML.py`,
`xml2csv.py`, `Dockerfile` и `requirements.txt`, полученных из ветки `master`.
Синтаксис четырёх Python-файлов проверен через `ast.parse` без импорта и
исполнения. Исходная программа и Docker-образ не запускались. Поэтому
выводы о поведении при запуске, кроме подтверждённой ошибки синтаксиса,
представляют анализ кода, а не результаты динамических испытаний.

Проект объединяет запуск сканеров, преобразование результатов в CSV,
табличную обработку и интерактивный поиск информации о портах. Название
коммита описывает экспертную систему, однако полноценный механизм правил
или обучаемое дерево решений в исследованных исходных файлах не обнаружены.

## Назначение файлов

| Файл | Назначение по фактическому содержимому |
| --- | --- |
| `main.py` | Интерактивный ввод цели, последовательный запуск сканеров, вызов конвертеров, обработка pandas/NumPy и поиск сведений в интернете |
| `convJson.py` | Чтение двух фиксированных JSON-файлов через pandas и сохранение двух CSV-файлов |
| `convXML.py` | Частично дублирующий основной сценарий файл с ошибкой синтаксиса; не является работоспособным самостоятельным XML-парсером |
| `xml2csv.py` | Разбор Nmap XML через ElementTree, вывод CSV и вспомогательная фильтрация/статистика |
| `Dockerfile` | Попытка установки инструментов и запуска Python-программы в контейнере |
| `requirements.txt` | Закреплённые версии Python-зависимостей |
| `nmap_output.xml`, `masscan_output.json`, `nikto_output.json` | Файлы результатов сканеров, присутствующие в структуре репозитория; содержимое этих образцов не анализировалось в данной проверке |

На странице репозитория также видны каталоги `.idea` и `venv`. Наличие
среды разработки и виртуального окружения в репозитории затрудняет
отделение исходного кода от локальных артефактов. Их полное содержимое
в рамках этой проверки не исследовалось.

## Восстановленная архитектура

Поток в `main.py`:

1. Пользователь вводит адрес цели.
2. Nmap, Nikto и Masscan запускаются последовательно через `subprocess.run`.
3. JSON преобразуется в CSV через `convJson.py`, XML — через `xml2csv.py`.
4. CSV читаются в pandas, вложенные данные разбираются через `ast.literal_eval`.
5. Поля портов, TTL и времени участвуют в вычислениях NumPy, включая корни полиномов.
6. Результаты выводятся в консоль с помощью `tabulate`.
7. Пользователь выбирает порт и количество результатов поиска.
8. Программа выполняет Google-поиск, случайно выбирает одну ссылку,
   загружает страницу и печатает извлечённый текст.

Это тесно связанный интерактивный сценарий. В исследованных исходниках нет
единого выходного объекта инцидента с полями `detected`, `risk_score`,
`category` и `recommendations`, соответствующего схеме новой системы.

## Подтверждённые ограничения

| Наблюдение | Основание в коде | Последствие |
| --- | --- | --- |
| Ошибка синтаксиса | В `convXML.py` блок `try` в начале файла не завершён перед `import subprocess` на строке 42; `ast.parse` возвращает `expected 'except' or 'finally' block` | Файл не может выполняться как Python-программа в представленном виде |
| Небезопасное формирование команд | В `main.py` ввод `ip` подставляется в строковые команды, выполняемые с `shell=True` | Специальные символы shell могут менять смысл команды; отсутствует явная проверка адреса |
| Нет контроля успешности сканеров | Вызовы `subprocess.run` не используют `check=True`, таймауты или проверку `returncode` | Последующая обработка может продолжиться после ошибки сканера |
| Фиксированные имена результатов | Повторно используются `nmap_output.xml`, `masscan_output.json` и `nikto_output.json` | Нет изоляции запусков; возможна обработка старых результатов после сбоя |
| Жёсткие пути | Чтение CSV привязано к `/media/sf_Kali-linux/LastSborka/` | Перенос на другую машину требует изменения кода или воспроизведения пути |
| Повторное определение функции | `convert_json_to_csv` определена дважды; вторая версия заменяет первую и игнорирует аргумент функции | Интерфейс функции не соответствует её поведению |
| Аргумент конвертера фактически не используется | `main.py` передаёт `-i`, но `convJson.py` не разбирает аргументы и каждый раз читает оба фиксированных JSON | Нельзя считать вызовы независимой конвертацией выбранного файла; возможно повторное преобразование обоих файлов |
| Потеря нескольких портов | При разборе Masscan в `main.py` извлекается только `result[0]` из списка портов | Остальные порты одной записи не включаются в эти извлечённые поля |
| Необоснованное преобразование признаков | Номера портов, TTL, временные значения и корни полиномов участвуют в вычислениях без описанной модели угроз или валидации | По коду нельзя установить обоснованность этого показателя как оценки риска |
| Недетерминированный поиск | Используются Google-поиск и `random.randint` для выбора страницы | Объяснение результата зависит от внешней выдачи и случайности |
| Нет сетевого таймаута HTTP | `requests.get(response)` вызывается без `timeout` | Ожидание внешнего сайта не ограничено на уровне данного вызова |
| Обобщённая диагностика ошибок | Общий `except Exception` завершает работу сообщением о проблемах Masscan | Ошибки CSV, поиска или иных компонентов могут ошибочно выглядеть как ошибка Masscan |
| Последовательный сбор | Вызовы сканеров следуют друг за другом | В исследованном сценарии нет конкурентного запуска сканеров |

Важно: из повторного определения `convert_json_to_csv` нельзя сделать вывод,
что Nikto вообще не конвертируется. Фактический `convJson.py` читает оба
файла при каждом запуске. Проблема состоит в неверном интерфейсе, фиксированных
путях и повторной работе, а не в доказанном отсутствии конвертации Nikto.

## Контейнер и зависимости

В `Dockerfile` каталог `nikto-2.5.0` перемещается в `/opt/nikto`, после чего
символическая ссылка создаётся на
`/opt/nikto/nikto-2.5.0/program/nikto.pl`. При обычной структуре архива и
отсутствующем ранее `/opt/nikto` это добавляет лишний уровень каталога;
ожидаемым путём после перемещения был бы `/opt/nikto/program/nikto.pl`.
Это вероятная ошибка пути по статическому анализу; сборка образа не выполнялась.
Кроме того, указанное значение PATH начинается с `opt/`, без начального `/`.

Закрепление версий в `requirements.txt` полезно для повторяемости. Однако
само наличие списка зависимостей не подтверждает совместимость всех пакетов,
корректность системных инструментов или успешность контейнерной сборки.
Нельзя автоматически считать перечисленные версии уязвимыми без отдельной
проверки: такой аудит здесь не проводился.

## Сопоставление с новой системой

| Область | Исходный проект | Security Scan Analysis Platform |
| --- | --- | --- |
| Представление данных | CSV и связанные pandas-таблицы | Нормализованные JSON-отчёты с целью и массивом находок |
| Nmap | Python ElementTree → CSV | C++/libxml2 → JSON → Python-нормализация |
| Masscan и Nikto | Фиксированные файлы, общая конвертация pandas | Отдельные нормализаторы и проверка целевого адреса |
| Принятие решений | Табличные вычисления и интерактивный поиск | Внешние YAML-правила, риск, категории, рекомендации и отдельный классификатор |
| Правила | Отдельный механизм правил в просмотренном коде не найден | Валидация, снимки и восстановление версий через Java/Python |
| Интерфейс | Консоль | Go REST API и JavaScript-дашборд |
| Выполнение | Последовательные сканеры | Python ThreadPoolExecutor для сканеров; фоновая задача в Go |
| Изоляция результатов | Постоянные имена файлов | Отдельный каталог каждого запуска и журнал статусов сканеров |
| Ошибки сбора | Коды завершения не проверяются | При сбое сканера не публикуется полная успешная оценка |
| Оценка качества | Модуль метрик в просмотренных файлах не найден | Синтетические датасеты, матрица ошибок и Precision/Recall/F1 |
| Документация | На просмотренной странице отсутствует README | README и отдельное руководство по живому сканированию |

Новая реализация проверена на локальной лабораторной цели `192.0.2.2:8000`.
Запуск из дашборда и независимый запуск `run_system.sh` дали по 16 находок:
Nmap — 1, Masscan — 1, Nikto — 14. В первом зафиксированном запуске интервалы
работы трёх сканеров перекрывались. Это подтверждает интеграцию в лаборатории,
но не производительность на больших сетях и не полноту обнаружения угроз.

## Границы выводов

- Нельзя утверждать, что исходный проект содержит «жёстко зашитые экспертные
  правила»: в проверенном коде явный механизм таких правил не найден.
  Формулировка задания является описанием предполагаемой проблемы,
  а не заменой анализа исходников.
- Не проводилось сравнение скорости Python- и C++-парсеров на общем наборе
  больших файлов. Использование C++ само по себе не доказывает ускорение.
- Новая система тоже является учебным прототипом: цель живого сканирования
  фиксирована, история API хранится в памяти, модель обучена на малом
  синтетическом наборе, а нормализованная серьёзность многих находок — `info`.
- Отсутствие сработавших правил не доказывает безопасность цели.
- Для окончательного отчёта необходимо сохранить различие между статически
  найденными проблемами исходного проекта и реально выполненными тестами
  новой реализации.

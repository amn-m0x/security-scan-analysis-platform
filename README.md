 Security Scan Analysis Platform

An educational security analysis platform that normalizes Nmap,
Masscan and Nikto reports, evaluates YAML rules, and provides a
decision-tree prediction alongside the rule-based assessment.

 Components

- C++: Nmap XML parser using libxml2.
- Python: report normalization, merging, rule engine and decision tree.
- Go: REST API.
- JavaScript: browser dashboard.
- Java: rule validation, snapshots and restoration.

 Requirements

- Ubuntu/Linux
- Python 3 with venv and pip
- C++17 compiler, pkg-config and libxml2 development headers
- Go
- Java JDK for the rule manager
- Nmap, Masscan and Nikto for live scans

The sample demo uses stored scan fixtures and does not run live scanners.

 Installation

Install the basic dependencies on Ubuntu:

bash
sudo apt update
sudo apt install -y git build-essential pkg-config libxml2-dev python3-venv python3-pip golang-go default-jdk


Clone the repository and prepare the Python environment:

bash
git clone https://github.com/amn-m0x/security-scan-analysis-platform.git
cd security-scan-analysis-platform
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt


 Run the sample demo

Run from the project root:

bash
bash run_demo.sh


The script:

1. Builds the Nmap XML parser.
2. Normalizes the Nmap sample.
3. Normalizes the Masscan sample.
4. Normalizes the Nikto sample.
5. Merges the normalized findings.
6. Trains and evaluates the decision tree.
7. Runs both analysis methods.

Each run writes its scan reports to a new directory under
results/demo-*. The script prints the exact output directory.

The combined sample contains six findings for 192.0.2.10.
The expected rule-based risk score is 9.0.

 Decision tree

The training dataset is stored in:

text
data/samples/tree_dataset.json


To train the model separately:

bash
.venv/bin/python python/train_tree.py


Generated artifacts include:

text
results/decision_tree.joblib
results/decision_tree.txt
results/tree_evaluation.json


Train the model before using the analysis CLI or API.
Running the sample demo also performs this step.

Only load model files generated by this project in a trusted environment.

The rule-based assessment remains in incident.
The separate prediction is returned in decision_tree, including
whether its detection result agrees with the rule engine.

 Start the API and dashboard

From the project root, after training the model:

bash
mkdir -p build results
go build -o build/api go/api.go
./build/api


Keep this terminal open while using the API.

The server listens at:

text
http://127.0.0.1:8080


Endpoints:

- POST /analyze: analyze a normalized JSON scan report.
- GET /incidents: retrieve reports stored by the running API.
- GET /: open the dashboard.

The API retains up to 100 reports in memory.
Restarting it clears this report history.

The dashboard accepts normalized JSON reports containing
scan_id, timestamp, target and findings.
Raw scanner output must be normalized first.

 Windows access to an Ubuntu VirtualBox guest

For the tested NAT setup, configure a VirtualBox forwarding rule:

- Protocol: TCP
- Host IP: 127.0.0.1
- Host port: 2222
- Guest port: 22

The Ubuntu guest must have a running SSH server.

In Windows PowerShell, replace YOUR_UBUNTU_USER with your guest username:

powershell
ssh -N -L 18080:127.0.0.1:8080 -p 2222 YOUR_UBUNTU_USER127.0.0.1


Keep PowerShell open and visit:

text
http://127.0.0.1:18080


 Java rule manager

Compile the rule manager:

bash
mkdir -p build/java
javac -d build/java java/RuleManager.java


Active rules are stored in rules/rules.yaml.
Version snapshots are stored in rules/versions/.
Restoration validates the selected rules and backs up the previous
active rules before replacing them.

 Evaluation and limitations

The decision tree uses eight synthetic training scenarios and six
held-out synthetic test scenarios.

Observed test results:

 Metric  Value 
 ---  ---: 
 True positives  2 
 False positives  1 
 False negatives  1 
 True negatives  2 
 Precision  0.6667 
 Recall  0.6667 
 F1  0.6667 

These small educational datasets do not establish real-world accuracy.
Agreement between the rule engine and the tree does not prove that
either result is correct.

Findings and alerts are indicators requiring review, not proof of
a successful attack.

Live scanner outputs have been exercised separately in the local lab.
The sample demo itself operates on fixtures.

Only scan systems you own or are authorized to test.
The API is intended for local educational use.

 Generated files

results/, build/ and .venv/ are excluded from version control.
After a fresh clone, install dependencies and run the demo to regenerate
the parser, model and sample analysis results.
